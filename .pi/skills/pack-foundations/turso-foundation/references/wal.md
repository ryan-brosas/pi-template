# Turso — WAL Reference

Source-grounded reference for `core/storage/wal.rs` (10,620 lines walked in full incl. test module) + frame codec in `core/storage/sqlite3_ondisk.rs`. Written by the forge worker; anchors verified against source.

## P1 — Frame format: 24-byte header + cumulative Fibonacci checksum chained per generation

- **WHO** every reader (`read_frame`/`read_frames_batch` verify via decode), the recovery scanner, encryption/page-codec users. Byte-compatible with SQLite's WAL.
- **WHAT** frame = 6 big-endian u32s (page_number, db_size, salt_1, salt_2, checksum_1, checksum_2 = 24 bytes) + page body. Each checksum covers frames[0..8] then the body, seeded from the previous frame's cumulative value — an unbroken chain from the 32-byte WAL header.
- **WHEN** every append (prepare_frames / append_frames_vectored / write_frame_raw); every recovery step. `db_size>0` marks a COMMIT frame (transaction boundary).
- **WHERE** constants `sqlite3_ondisk.rs:412-417` (WAL_HEADER_SIZE=32, FRAME_HEADER=24, MAGIC_LE=0x377f0682, BE=LE|1); header serialization :2137-2165; frame-header build :2099-2118 ("The caller must write every byte after [WAL_FRAME_HEADER_SIZE] before computing the frame checksum"); chain recompute :2120-2133; endian rule :2190-2235 ("checksum values are always stored… big-endian regardless of which byte order is used"; "s0 += x(i) + s1; s1 += x(i+1) + s0" — Fibonacci weights in reverse); commit marker :507-509; generation seed `wal.rs:4801-4830` ("The first frame of a generation always chains from the WAL header checksum"); offset math :5225-5232.
- **WHY** The chain makes torn/garbage tails detectable at EXACTLY the first bad frame (recovery self-terminates). Salts bind frames to one generation so stale frames after RESTART/TRUNCATE are rejected, not resurrected. db_size>0 ensures crash recovery never exposes partial transactions. Generation-seed rule prevents a subtle corruption: frame 0's checksum would predate the new header — with comment about savepoint rollbacks reinstalling positions captured in that window.
- **HOW** prepare_transformed_frame asserts page_number>0 and page-size match, builds the header, applies PageTransform (Codec encode | Checksum | copy), then overwrites bytes 16..24 with the chained value. Readers mirror per-frame decode; short reads → ShortReadWalFrame, page mismatch → WalFramePageMismatch (:3630-3700).
- **LESSON** Chain integrity into the framing itself: one cumulative checksum seeded per generation turns arbitrary media corruption into a precise, self-terminating truncation point.
- **PROBE** `read_wal_header` (~10060) parses raw bytes asserting magic/3007000/page_size 4096/checkpoint_seq==1 post-TRUNCATE; codec round-trips at ~6570-6640 assert byte-exact decode and reject wrong buffer sizes.

## P2 — Commit ordering: prepare (pure) → durable write → publish

- **WHAT** prepare_frames computes frames WITHOUT touching shared state; caller submits pwritev+fsync; ONLY commit_prepared_frames advances max_frame/last_checksum and caches page→frame mappings (visibility). Spill appends optimistically but publish visibility only in the I/O completion callback.
- **WHERE** doc+prepare :4790-4930 (three-phase protocol verbatim; prev-chaining); local-vs-authority branch :4840-4870 with turso_assert "connection WAL position must not be behind the committed high-water mark"; commit_prepared_frames :4935-4955; spill publication :5060-5085 ("populating it here -- from the write completion callback -- is what publishes the frames. Doing it before durability would let a reader or checkpoint pick up a frame whose bytes are not on disk yet"); optimistic cursor rationale :5090-5115; append_frames_vectored safety doc :4960-4965.
- **WHY** Publishing before durability → readers/checkpointers consume frames lost by crash (torn DB matching no committed prefix). Blocking inside spill would deadlock single-threaded event-loop callers ("Must NOT block for durability here"). So: "my cursor advanced" (private, recoverable) ≠ "frames are visible" (only after durable write).
- **HOW** complete_append_frame sets dirty, stores last_checksum/max_frame, cache_frame(page,frame); finish_append_frames_commit bumps transaction_count and publishes WalCommitState (Release-store; SHM backend mirrors checksum into the header for cross-process authority).
- **LESSON** Separate optimistic private cursors from globally visible publication points — and make the I/O completion callback, not the submitter, the only place visibility is granted.
- **PROBE** ~6415-6450: after a spill, get_max_frame()==1 while get_max_frame_in_wal()==0, and next prepare assigns frame_id 2; failure injection ~6640: failed prepare leaves max_frame==0 and find_frame(43)==None.

## P3 — Recovery: streaming poll-driven scan that stops at first invalid frame and truncates to last COMMIT

- **WHAT** BuildSharedWal drives NeedHeaderRead → AwaitHeader → ChunkLoop → AwaitChunk → Done over StreamingWalReader: validate header, read aligned ~16MB chunks, verify salts+cumulative checksum, buffer pending page→frame entries, flush into the frame cache ONLY on commit frames; max_frame ends at last_valid_frame.
- **WHEN** first open of an existing -wal; in host_shared mode whenever classify_authority_snapshot_against_wal returns RebuildFromDisk (reasons enumerated :5540-5555: WalHeaderUnreadable/Mismatch, WalLengthMismatch, WalTooShortForSnapshot, LastFrameMissing/NotCommit/SaltMismatch/ChecksumMismatch).
- **WHERE** entry :5755-5790; authority gate :5602-5720; scanner sqlite3_ondisk.rs:1450-1955 (progress guard "No forward progress -- treat as end of valid log"; chunk base 16MB frame-aligned "to avoid splitting frames across reads"; stop conditions verbatim: "unexpected page_no/salt mismatch/checksum mismatch, stop reading WAL"; commit-gated publication :1886-1903; finalize :1917-1955 using "checksum of last valid commit frame, not necessarily the last frame"; high-water seeding :1905-1913 — recovery populates the cache directly so it must seed the rewind detector's watermark, else post-recovery slot reuse "surfacing as 'non-index page' / corruption").
- **WHY** Crash leaves arbitrary bytes past the last synced frame; trusting beyond the first violation replays corrupt pages. Commit-gated publication = SQLite's whole-transaction rule. High-water seeding closes the specific hole where the rewind detector misses the first post-recovery slot reuse.
- **LESSON** Recovery is not "read what is there" but "prove what is trustworthy, then discard the rest at the first broken link" — and every cache populated outside the normal write path must still satisfy that path's invariants (seed your watermarks).
- **PROBE** ~8285: one-byte truncation → RebuildFromDisk(WalLengthMismatch); zeroed header → WalHeaderUnreadable; end-to-end ~8540: rebuilt max_frame==1, loaded_from_disk_scan=true, frame_cache has 7→[1].

## P4 — Checkpointing: five states under ordered exclusive locks, fsync barrier before backfill, read-mark-bounded mxSafeFrame, truncation deferred past DB sync

- **WHAT** Start → SyncWal → Processing → DetermineResult → Finalize. Lock order: CHECKPOINTER, then WRITER (+read-mark 0) for Full/Restart/Truncate. SyncWal fsyncs the WAL BEFORE backfill. Processing pipelines ≤MAX_INFLIGHT_READS reads and vectored writes (WriteBatch merges contiguous runs). DetermineResult enforces require_all_backfilled for non-Passive; Finalize holds locks through the pager's DB-file sync + nbackfills publish.
- **WHERE** threshold :3965-3969 (max_frame > threshold + nbackfills; default 1000 :5175); SyncWal doc :2405-2422 ("under synchronous=NORMAL commits do not fsync the WAL, so without this barrier a crash mid-backfill could persist some backfilled pages while recovery drops the unsynced tail — a torn database matching no committed prefix"); lock-order doc :3105-3112; locality note (reads by frame id, writes by page id — "the more consecutive page IDs submitted together, the fewer writev syscalls"); stuck guard InternalError "checkpoint stuck"; mxSafeFrame algorithm :5130-5160 with sqlite wal.c commentary ("must never overwrite a page some active reader might still need from the WAL"); DEFERRED truncation NOTE :5062-5068 ("if a crash occurs after WAL truncation but before DB sync, the data would be lost") + trait contract :795-800; guard handoff :5085-5090.
- **WHY** Each guard kills one durability bug: no barrier → torn DB under synchronous=NORMAL; no mxSafeFrame → backfill destroys a reader's snapshot content; truncate-before-sync → data loss; releasing locks before nbackfills publish → a writer restarts the generation mid-publish.
- **HOW** RAII CheckpointLocks ("no locks leaked during errors"); CompletionGroup loop drains reads into WriteBatch (BTreeMap neighbor probe merges runs), flushing when full || (len≥512 && avg_run≥32) || drained; cancel-on-first-error drains all inflight.
- **LESSON** Durability ordering is the whole game: sync the log before copying from it, sync the DB before shrinking the log, keep the mutexes until the last durable fact is published.
- **PROBE** ~9770-9825 two readers + Passive checkpoint backfills exactly r1's max while r2 keeps its snapshot; ~10310 Busy FULL must leave nbackfills==0; ~9930 TRUNCATE → size 0, checkpoint_seq==1.

## P5 — Snapshot isolation via read-mark slots: slot 0 bypasses WAL; stale writers get BusySnapshot, not Busy

- **WHAT** begin_read_tx loads a WalSnapshot; if fully backfilled take slot 0 (ignore WAL entirely), else claim the free slot with the best mark (exclusive CAS set_value_exclusive(max_frame)) then RE-validate after locking. Write upgrade fails with BusySnapshot if the shared snapshot moved. Savepoint rollbacks restore (frame, checksum, checkpoint_seq) and ASSERT generation match.
- **WHERE** sqlite wal.c commentary ported :2800-2860 (aReadMark rules verbatim); slot semantics :2845-2852; TursoRwLock 64-bit packing (writer bit | 31 reader bits | 32-bit value, one cache line) :230-330; validate-after-lock :997-1055; retry curve :3355-3395 (quadratic (cnt−9)²×39µs mirroring SQLite, cap 100); BusySnapshot rule :3405-3430 ("Retrying with busy_timeout will NEVER HELP"); savepoint generation assert :4520-4555 (turso needs no SQLite-style clamping — positions captured under the held write lock make cross-generation impossible by construction).
- **WHY** Read-marks convert "which frames may I overwrite?" into lock-compatible integers. Slot 0 kills WAL lookups in the steady state and lets RESTART proceed once readers drain. Distinguishing BusySnapshot prevents clients busy-waiting on a conflict only a FRESH read transaction can fix.
- **LESSON** Encode snapshot bounds as values protected by their own locks so readers, writers, and maintenance coordinate through DATA rather than conversations.
- **PROBE** ~10145-10205 slot-0 behavior post-backfill (find_frame None); vacuum-guard leak probe ~9330-9365 forces Retry by occupying all four slots.
